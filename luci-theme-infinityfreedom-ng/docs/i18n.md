# Theme internationalization

The theme uses LuCI's normal translation pipeline, not a separate browser-side language switcher.

## Catalogs and packaging

- English source literals: `_('English text')` in ucode templates.
- Template: `po/templates/infinityfreedom-ng.pot`.
- Simplified Chinese: `po/zh_Hans/infinityfreedom-ng.po`.
- Standard labels (for example `Log in`, `Reset`, `Username`, `Password`, `Close`) reuse `luci-base` translations.
- Theme-owned translations are built by `luci.mk` using `po2lmo` and installed as `infinityfreedom-ng.zh-cn.lmo` under `/usr/lib/lua/luci/i18n`.
- The generated language package is `luci-i18n-infinityfreedom-ng-zh-cn`. Include it together with `luci-i18n-base-zh-cn` in Chinese firmware. The theme package alone is not its Chinese translation package.
- Enable `CONFIG_LUCI_LANG_zh_Hans=y` for the standard language selection mechanism. Use `make defconfig` and inspect the generated translation-package selection when integrating the feed into a firmware tree.

LuCI's dispatcher loads installed catalogs for the selected language before rendering templates, including the anonymous login page. No login-only JavaScript translation fetch is necessary. Without a matching catalog the English source text is shown.

## Scope

Login instructions, placeholders, validation messages, buttons and accessible password-toggle labels; palette labels; firmware resource links; footer links; page-description tooltip; existing theme-specific refresh/logout/loading messages and the no-password warning.

Palette identifiers, UCI values, URLs, DOM identifiers, user-defined menu labels, brand names and third-party vendor assets are not translated. English is the source language and needs no duplicate English PO file. Other languages can be added under `po/<language>/` through the same LuCI build rules.

## JavaScript strings

Theme-owned JavaScript does not assume that LuCI's JS `_()` function has loaded. The server translates a template attribute, and `ngRender.js` or the login handler reads that DOM attribute. This also avoids inserting translated strings directly into JavaScript source. Password-toggle labels update on show, hide and form reset.

## Maintenance and checks

Add new English keys through `_()`, update the POT and language catalogs, and reuse base keys exactly (for example `Log in`, not `Login`). Keep both headers' palette label definitions synchronized. The theme POT contains theme-owned keys; standard LuCI base keys remain in the base catalog.

From the repository root:

```sh
uv run --with polib python scripts/check-i18n.py --luci-base-po /path/to/luci/modules/luci-base/po/zh_Hans/base.po
node scripts/test-login-i18n.cjs
node --check luci-theme-infinityfreedom-ng/htdocs/luci-static/infinityfreedom-ng/assets/js/ngRender.js
git diff --check
```

The coverage checker checks literal template keys, PO/POT consistency, untranslated placeholders and ARIA labels, Chinese source keys and hard-coded Chinese in templates and `ngRender.js`. It is not a complete HTML/ucode parser, does not validate dynamic menu labels, and does not prove live rendering.

Before release, compile the PO with LuCI's real `po2lmo`, build both theme and translation packages, install both, clear LuCI caches, and verify anonymous login plus logged-in menus in Chinese and English. Check password visibility/reset behavior and palette switching. Source checks or a Node handler test do not replace router/browser acceptance.
